# ТЗ v2 — «Собранный Хозяин»

Ежедневная операционка на телефоне. Не витрина личного бренда.

## Зачем

v1 превратился в справочник о личном бренде (10 вкладок: дашборд,
ядро бренда, визуальный код, речь, управление, контент, энергия,
трекер, справочник, империя). Открывать это каждый день незачем —
оно не про действие, оно про документацию.

v2 — наоборот: два экрана, оба про то, что делать прямо сейчас.
Всё остальное (архетипы, манифест, портфель бизнесов) никуда не
делось, просто стало справочным инструментом внутри «Ещё», а не
лицом приложения.

## IA

- **Сегодня** — единственный экран, который открывается по умолчанию.
- **Ещё** — плоский список из 5 инструментов, без вложенной навигации.

Никакой верхней панели вкладок, как в v1. Один экран = одно действие.

## Сегодня — утренний ритуал

Показывается один раз в день, при первом открытии после полуночи.
Пройденный ритуал сохраняется под сегодняшней датой; повторное
открытие в этот же день сразу показывает статус-вид (ниже).

### 1. Щель
Один экран паузы перед началом дня. Короткая строка + кнопка
«Готов». Без таймера и прочих украшений — просто осознанная секунда
перед тем, как начать.

> Пауза. Прежде чем войти в день — одна секунда тишины.
> [Готов]

### 2. 3 шкалы
Замена пяти ползункам v1 (sleep/body/mood/clarity/nerves) на три:

- **Тело** — сон + физическое состояние
- **Голова** — ясность, фокус
- **Дух** — настроение, нервы, заряд

Каждая — слайдер 1–10, сумма — счёт /30. Интерпретация — короткая,
директивная, в его голосе (адаптация текста из v1 `updateStateScore`):

- ≥24: «Отличное состояние. Можно решать сложные задачи и вести переговоры.»
- 18–23: «Нормальный рабочий день. Избегай лишнего хаоса.»
- 12–17: «День упрощать. Меньше решений, больше восстановления.»
- <12: «Не геройствовать. Только обязательное + восстановление.»

### 3. Одно главное
Одно текстовое поле. Жёсткое ограничение — один слот, не список.
Смысл шага именно в том, чтобы заставить выбрать одно.

### 4. 3 якоря
Три фиксированных текстовых слота с чекбоксом у каждого. Без
подзадач, без времени — просто три опорные точки дня.

### После ритуала: статус-вид
Счёт состояния, главное (с чекбоксом), три якоря (с чекбоксами),
кнопка «Закрыть день» (активна весь день, не только вечером).

## Сегодня — закрыть день

Тот же 4-польный журнал, что уже был в v1 (`saveJournal`), просто
вынесенный из «Трекера» в главный экран и переименованный в явный шаг
ритуала:

- Главное (что реально сделано)
- Что вымотало
- Переношу на завтра
- Отпускаю

После сохранения день фиксируется в истории, статус-вид показывает
«День закрыт» вместо кнопки закрытия.

## Ещё — 5 инструментов

1. **Речь** — 12 готовых идей для контента из v1 (`contentIdeas`,
   сохранить как есть — это его реальный голос, не сгенерированный
   текст) + кнопка «ещё идея» (случайная из массива). Копирование в
   буфер, как в v1.
2. **Протоколы** — 5-польный генератор формулировки задачи
   (что/кто/срок/результат/последствие) из v1 (`generateTask`), без
   изменений в логике.
3. **Фото-трек** — одно фото в день, необязательно. Хранится в
   **IndexedDB** (не localStorage — квота ~5-10MB не выдержит фото за
   год, IndexedDB не имеет этого ограничения, при этом остаётся
   100% клиентским хранилищем без бэкенда). Показывается лента
   последних фото с датами.
4. **Справочник** — сжатая версия статики v1: архетипы (Хозяин/
   Наставник/Искатель), манифест, карточки бизнесов (Империя) —
   один длинный экран с поиском (переиспользовать `filterReference`
   из v1), а не отдельные вкладки.
5. **История** — список закрытых дней (дата, счёт состояния,
   4 поля журнала), с возможностью удалить запись — паттерн
   `loadStateHistory`/`deleteHistoryEntry` из v1, адаптированный под
   новую структуру дня.

Плюс отдельная строка **Экспорт** — выгрузка всех данных (дни,
протоколы, журнал) одним JSON-файлом через `Blob`/`<a download>`.
Единственная страховка при отсутствии бэкенда: если очистить кэш
Safari или сменить телефон — данные пропадут без предупреждения,
если их не выгрузить самому. Явно сказано в интерфейсе рядом с
кнопкой.

## Данные

Новое пространство ключей `sobrannyi.v2.*` в localStorage — старые
ключи v1 (`stateHistory`, `journalEntries`) не читаются и не
мигрируются: разная структура, риска трактовать неправильно нет
смысла нести. Они просто остаются неиспользуемым мусором в
localStorage браузера, ничего не ломают.

```
sobrannyi.v2.days = {
  "2026-08-23": {
    ritualDone: true,
    scales: { body: 8, head: 7, spirit: 9 },
    mainTask: { text: "...", done: false },
    anchors: [{ text: "...", done: false }, ...3],
    closed: false,
    journal: null | { main, drain, tomorrow, release, ts }
  }
}
sobrannyi.v2.protocols = [ { text, ts }, ... ]   // история сформированных задач
```

IndexedDB: база `sobrannyi-photos`, store `photos`, записи
`{ date, blob, ts }`.

## Технически

Фронтенд остаётся статикой без сборки — HTML/CSS/JS, тот же паттерн
деплоя (nginx:alpine, `/opt/boss-brand/site`). Добавляются
`manifest.json` (иконка, `display: standalone`, тёмная тема) и
минимальный `sw.js` (кэш статических файлов), чтобы «Добавить на
домашний экран» реально работало офлайн.

Дополнительно — один маленький бэкенд-контейнер только для
Telegram-логина (см. раздел выше), остальная логика (ритуал, шкалы,
Ещё-инструменты) как и раньше работает полностью на клиенте.

Тёмная тема, mobile-first, один слайдер экрана — продолжение
эстетики v1 (`#0a0a0a` фон), не новый визуальный язык с нуля.

## Вход через Telegram, жёстко привязанный к id

По просьбе Алексея: логин через Telegram Login Widget, первый
залогинившийся id — единственный, кому разрешён вход, остальные
получают отказ.

**Почему это ломает «статика без бэкенда» и что вместо этого:**
Telegram Login Widget возвращает `id, first_name, username, photo_url,
auth_date, hash`. `hash` — HMAC-SHA256 от остальных полей на секрете
`SHA256(bot_token)` — проверить эту подпись можно только зная
bot_token, а токен нельзя класть в клиентский JS (любой откроет
DevTools и подделает данные). Значит нужен маленький бэкенд, только
для этого:

- Новый контейнер `boss-brand-auth` (Python, FastAPI/uvicorn,
  минимальный образ) рядом с существующим `boss-brand` (nginx).
- Один POST `/api/telegram-auth`: проверяет подпись, проверяет
  `auth_date` (не старше суток — защита от replay), затем:
  - если в БД ещё нет запертого id — записывает id этого пользователя
    как владельца, выдаёт сессию;
  - если id совпадает с уже запертым — выдаёт сессию;
  - если id другой — 403, без сессии.
- Хранилище — файл SQLite на volume (`locked_owner`, одна строка) +
  подписанная HttpOnly-кука как сессия (HMAC на серверном секрете,
  без внешних auth-библиотек).
- Caddy: `boss.zima.spa` — `/api/*` идёт на `boss-brand-auth:8000`,
  всё остальное — как раньше, на `boss-brand:80`. Basic auth Caddy
  **остаётся** (второй, независимый слой — Telegram-логин не
  заменяет его, а добавляется поверх).
- Фронтенд: экран входа с виджетом Telegram перед экраном «Сегодня»,
  пока нет валидной сессии; `GET /api/me` на загрузке для проверки.

**Нужно от Алексея, чтобы это заработало** (не могу сделать сам):
токен Telegram-бота (свой существующий или новый через @BotFather —
`/newbot`, затем `/setdomain boss.zima.spa` на этот же бот) — без
токена виджет не подключить и подпись не проверить.

## Не в скоупе v1

- Бэкенд/облачная синхронизация — сознательно не делаю, чтобы не
  усложнять и не менять паттерн деплоя. Экспорт — единственная
  страховка.
- Уведомления/пуши о ритуале — не поддерживаются браузером без
  бэкенда для PWA такого типа надёжно; не включаю, чтобы не обещать
  то, что не будет работать.
- Многодневные/повторяющиеся якоря — каждый день начинается с чистого
  листа, намеренно.
